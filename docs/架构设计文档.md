# 架构设计文档

## 1. 总体架构
系统采用经典的「发布—订阅」分层结构，由全局唯一的 ROSCore 调度中心维护节点与话题的映射关系。各节点之间不直接引用，全部通过核心中转消息，实现松耦合。

```
┌─────────────┐   publish(msg)   ┌──────────────────────────┐
│  Publisher  │ ───────────────▶ │          ROSCore         │
└─────────────┘                  │  (Singleton 单例)        │
                                 │  - topic -> subscribers  │
┌─────────────┐ ◀─────────────── │  - topic -> publishers    │
│ Subscriber  │   deliver(msg)    │  - registered names      │
└─────────────┘                  └──────────────────────────┘
```

## 3. 核心设计模式

### 3.1 单例模式（Singleton）
- **ROSCore**：全局唯一调度中心，通过 `getInstance()` 获取，构造函数私有，拷贝与赋值被禁用。
- **Logger**：全局唯一日志器，保证日志统一写入同一文件。

### 3.2 模板方法 / 多态
- **Node 抽象基类**定义 `init()`、`shutdown()` 纯虚接口，Publisher 与 Subscriber 各自实现具体行为；核心通过基类指针统一管理节点生命周期。

### 3.3 观察者模式
- 话题下的订阅者相当于观察者；发布者发布消息时，核心遍历该话题的订阅者列表，逐个回调 `onReceive()`。

## 4. 数据结构设计

| 容器 | 类型 | 作用 |
|------|------|------|
| topicSubscribers | `map<string, vector<NodePtr>>` | 话题 → 订阅者列表 |
| topicPublishers | `map<string, set<string>>` | 话题 → 发布者名称集合 |
| registeredNodeNames | `set<string>` | 已注册节点名，用于重复名校验 |
| allNodes | `vector<NodePtr>` | 全部节点，用于统一关闭 |

## 5. 消息流转流程

```
Publisher.publishMsg(text)
        │
        ▼
   构造 Message(含时间戳)
        │
        ▼
ROSCore.publish(topic, msg)
        │
        ├── 话题不存在 → WARN 日志，消息丢弃
        │
        ▼
遍历 topicSubscribers[topic]
        │
        ▼
Subscriber.onReceive(msg) → 打印时间戳与内容
```

## 6. 生命周期流程

```
启动主程序
   │
   ├── Logger.setLogFile() 初始化日志
   │
   ├── 创建 Publisher / Subscriber（构造时校验名称非空）
   │
   ├── 调用 init() → 注册到 ROSCore（校验话题、重复名）
   │
   ├── 发布消息 → 核心转发 → 订阅者回调
   │
   └── ROSCore.shutdownAll() → 遍历 allNodes 调用 shutdown() → 清空映射
```

## 7. 异常体系

| 异常类 | 触发场景 |
|--------|----------|
| NodeException | 节点名为空、节点名重复 |
| TopicException | 话题名为空 |
| MessageException | 消息内容为空 |

主函数通过 `try/catch` 分层捕获，异常以 ERROR 级别记录到日志，程序继续运行或正常退出。

## 8. 线程安全
- ROSCore 的注册与转发操作通过 `std::mutex` 保护（扩展多线程发布时可直接复用）。
- Logger 的日志写入通过独立互斥锁保护，避免多线程下文件交错写入。
