# ROS 模拟系统项目 — 需求文档

## 1. 项目背景
本项目使用纯 C++17 在不安装真实 ROS 的前提下，模拟 ROS（Robot Operating System）最核心的「节点—话题—发布/订阅」通信机制。目的是通过面向对象编程、设计模式与异常处理，理解机器人分布式通信的松耦合思想。

## 2. 项目目标
- 实现节点（Node）、话题（Topic）、消息（Message）、发布者（Publisher）、订阅者（Subscriber）的抽象与封装。
- 实现全局唯一的 ROS 核心调度器（单例模式），负责节点注册、话题映射与消息转发。
- 提供完整的节点生命周期：初始化 → 消息收发 → 全局关闭。
- 对非法输入与异常场景做容错处理，程序不崩溃并输出分级日志。
- 提供可选加分能力：复合传感器消息、日志持久化、多话题多节点并发演示。

## 3. 功能需求

### 3.1 基础功能（必做）
| 编号 | 功能 | 说明 |
|------|------|------|
| F1 | 多节点支持 | 可创建多个发布者与订阅者，建立话题—订阅映射 |
| F2 | 话题通信 | 发布者向话题发送消息，核心转发给该话题全部订阅者 |
| F3 | 生命周期管理 | 节点 init 初始化、shutdown 关闭，核心提供 shutdownAll 统一关闭 |
| F4 | 消息封装 | 消息携带内容与自动生成的时间戳 |
| F5 | 异常处理 | 空节点名、重复节点名、空话题、空消息、不存在话题等场景被捕获并提示 |
| F6 | 分级日志 | INFO / WARN / ERROR 三级输出到控制台，同时写入日志文件 |

### 3.2 加分功能
| 编号 | 功能 | 说明 |
|------|------|------|
| E1 | 复合消息 | SensorMessage 同时携带温度、湿度数据 |
| E2 | 日志持久化 | 所有日志追加写入 logs/ros_sim.log |
| E3 | 多话题演示 | 多个发布者、多个话题互不串台 |

## 4. 非功能需求
- **语言标准**：C++17
- **线程安全**：核心注册与日志写入使用互斥锁保护
- **可移植性**：同时支持 g++ (Linux/MinGW) 与 MSVC (Visual Studio)
- **可维护性**：类职责单一，头文件与实现分离

## 5. 术语定义
| 术语 | 含义 |
|------|------|
| Node 节点 | 系统最小功能单元，分为发布者与订阅者，拥有唯一名称 |
| Topic 话题 | 通信通道名称，发布者与订阅者通过话题解耦 |
| Message 消息 | 数据载体，包含业务内容与时间戳 |
| Publisher 发布者 | 绑定话题，向核心发送消息的节点 |
| Subscriber 订阅者 | 订阅话题，接收核心转发消息并触发回调的节点 |
| ROS Core | 全局唯一调度中心，维护注册信息并转发消息 |

## 6. 验收标准
1. 程序编译无错误，主程序运行退出码为 0。
2. 基础场景：一个发布者、两个订阅者，两条消息均被两个订阅者接收。
3. 异常场景：五类非法输入均被捕获，程序不崩溃。
4. 测试用例 7 项全部通过。
5. 日志文件成功生成并记录完整收发与异常信息。
